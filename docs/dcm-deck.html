ARCHITECTURE07 / 17

The distinction people miss

Three copies.
All can be stale.

A GIT REPOSITORY is a snapshot, not a live link — push a commit and it knows nothing until FETCH.

A workspace lives in your personal database. SHOW GIT REPOSITORIES won't list it, and a scheduled task can't read it.

GitHub is authoritative. The other two are caches.

What it returns · what Snowflake forgets

It names the column

ALTER TABLE …PRE.DIM_PBI_CAPACITIES
  columns:
    removed "HAND_ADDED_BY_A_HUMAN"
            VARCHAR(100), nullable

Not “a table differs.” The name, the type, and which way the fix runs — the difference between an alert worth waking for and one people mute.

Measured — 7+ plans, 4 deploys

SELECT PHASE, COUNT(*)
  FROM DCM_DEPLOYMENT_HISTORY(…)

  PHASE     N
  DEPLOY    4   ← no PLAN rows. none.

The drift check is the one thing Snowflake doesn't record. Deployments keep 12-month artifacts; plans keep nothing, with no ACCOUNT_USAGE view — so we keep our own log. It answers when did this drift start?

Thirteen findings. Four from deliberate sabotage.

Every failure we found was something reporting success without checking what it claimed to check.

This POC proved the database matches the repo. The same declarative project can prove the data passes — quality checks declared right beside the schema.

BEYOND SCHEMA15 / 17

beyond schema · examples

Declared beside the schema

-- in the same sources/definitions file
ATTACH DATA METRIC FUNCTION SNOWFLAKE.CORE.NULL_COUNT
  TO TABLE DEVELOP.PRE.DIM_PBI_CAPACITIES ON (ID)
  EXPECTATION no_null_ids ( VALUE = 0 );

ATTACH DATA METRIC FUNCTION SNOWFLAKE.CORE.DUPLICATE_COUNT
  TO TABLE DEVELOP.PRE.DIM_PBI_CAPACITIES ON (ID)
  EXPECTATION unique_ids ( VALUE = 0 );

The left side is always the keyword VALUE. No subqueries, no casts, no arithmetic — a check, not a query.

one command runs them all

$ snow dcm test PBI_CAPACITIES

  PASS  no_null_ids
  PASS  unique_ids
  FAIL  fact_not_empty  (VALUE 0)

Applies to deployed objects, after tasks and dynamic tables have refreshed. The same pass/fail gate can sit on landing, staging and presentation — so bad data is caught where it enters, not three dashboards later.
